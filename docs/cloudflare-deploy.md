# Cloudflare deployment

Production: https://ast.migos.club

PR preview example: https://pr123-dev.ast.migos.club

The application is generated by Nuxt into `.output/public`. Cloudflare Workers Static Assets publishes that directory directly with Wrangler. This avoids the incompatible `cf build` output specification.

The workflow deploys `ast-explorer` on pushes to `main` and `ast-pr-N` on same-repository pull requests. On close or merge, it removes the preview Worker and custom domain.

## GitHub Actions secrets

- `CLOUDFLARE_API_TOKEN`: token with Workers deployment and Workers Custom Domains permissions
- `CLOUDFLARE_ACCOUNT_ID`: Cloudflare account ID
- `CLOUDFLARE_ZONE_ID`: zone ID for `migos.club`

Never expose these credentials to forked pull requests.

## Validate locally

```sh
corepack enable
corepack prepare pnpm@12.21.0 --activate
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm generate
test -f .output/public/index.html
test -f .output/public/_headers
npx wrangler deploy --dry-run
```

For a manual production deployment with authorized credentials:

```sh
npx wrangler deploy --name ast-explorer
```

The `public/_headers` file specifies COOP `same-origin` and COEP `require-corp` for parsers that require cross-origin isolation. Verify these headers from the published domain, not only from the build output.
